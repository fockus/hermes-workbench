# Проверка выпуска с двумя нативными плагинами

Проверено на macOS arm64 с Python 3.14 и 3.11. Тест использует GitHub-источники из lock, изолированные HOME/TMPDIR и только новые prefix. Для повторения: `python3.14 -I -B tests/smoke_isolation.py --parent "$SCRATCH"` из checkout, где `$SCRATCH` — существующий временный каталог.

| Сценарий | Наблюдаемый результат |
|---|---|
| Чистая установка | Новый `--with-tui` выбрал `claude-graphite`, собрал JS и прошёл 56/56 целевых регрессий. Он и второй prefix без TUI включили `memory-bank` и `llm-wiki`. Wiki создала индекс двух страниц шаблона: без пользовательских источников и векторов. |
| Memory Bank через Hermes | В реальном диспетчере `/mb` указывает на поставляемый skill. Секция prompt содержит статус именно `profile/.memory-bank`; `resolve_session_env` вернул этот же `MB_PATH`. После `on_session_finalize` в handoff профиля A появился ID тестовой сессии. |
| LLM Wiki через Hermes | Все четыре инструмента попали в каталог штатных CLI toolsets. Через `model_tools.handle_function_call` прошли `status`, полнотекстовый `search`, построчный `read` и `graph`. Выход за корень при чтении отклонён. Это нативные вызовы, а не проверка одного manifest или CLI. |
| Разделение профилей | В обоих профилях метка сначала отсутствовала. Тест записал её в статус и документ только профиля A. Из рабочего каталога A его Hermes увидел метку через оба плагина. Hermes профиля B из **того же cwd** не нашёл её ни в prompt, ни в Wiki; прямое чтение документа A не удалось, handoff в B не появился. |
| Повтор и preflight | `--check --with-tui` на новом пути не создал prefix. На двух установленных prefix повтор в их режимах прошёл проверку артефактов после записи данных. |
| Фильтрация источников | Тестовый Git-сервер без фильтрации отвергнут. На сервере с фильтрацией Git отдал разрешённый файл, а объект синтетической `.memory-bank/record` остался отсутствующим даже в `.git`. Хеши отобранного публичного runtime проверяются до установки. |
| Регрессии упаковки | 9/9 unit-тестов; Ruff и ShellCheck без замечаний. Дополнительный режим `--wiki` сохранил отдельный CLI: проверены `ingest`, `index --lexical-only`, `search`, `read`, `lint`. |

Первый вариант теста дописывал метку после конца окна, которое читает хук Memory Bank (30 строк). Проверка корректно упала. Исправлен только синтетический fixture: метка помещается в начало статуса; проверка не ослаблена.

**Границы:** каталог инструментов Hermes сообщает об отсутствии авторизации Nous в чистых профилях — ключей там нет. Диалог с моделью, загрузка весов, semantic/hybrid, внешние провайдеры и полный upstream Python suite не проверялись. Для прежнего снимка профилей сопоставлялись только типы файлов, цели ссылок и время изменения по метаданным; содержимое личных файлов не хешировалось и не сравнивалось.

## Историческая проверка CLI-only поставки, до нативной интеграции Wiki

На macOS arm64 выполнены независимые установки базы и Wiki из публичных Git-источников в новые prefix. Для совместимости также собран новый `--with-tui` из чистого checkout публичного Hermes. Python базы 3.14.9, Wiki 3.11.15; uv 0.13.5.

| Проверка | Результат |
|---|---|
| Публичные pin и лицензии | Проверены `FETCH_HEAD^{commit}`, MIT notice и digest выбранных файлов каждого компонента. Лицензии обеих разработок Anton Ivanov совпали с байтами `LICENSE` на их pin. Для вложенных материалов superpowers сохранён MIT notice Jesse Vincent. |
| База без UI | `config get plugins.enabled --json` → `["memory-bank"]`. Обнаруженный `/mb` указал на публичный `commands/mb.md`. Зарегистрированный диспетчер Hermes прочитал canary из свежего проекта, вернул ему `MB_PATH` и `MB_SKILLS_ROOT`; `on_session_finalize` записал идентификатор сессии в `handoff/latest.md`; в изолированном `SOUL.md` появился блок правил. Это проверка хуков, не диалог с LLM. |
| Регрессия состава | Первая проба показала `rules sync skipped`: не хватало `adapters/_lib_agents_md.sh` и маркера корня bundle. Расширенный smoke упал на отсутствии блока правил в старой пробе и прошёл в новой чистой установке. |
| Standalone Wiki | В отдельном prefix установлены 35 пакетов по `requirements.lock`. Проверены `init`, `ingest`, `index --lexical-only`, `status`, `search --mode fulltext`, `read`, `lint`. Пример из README вернул `raw/example.md`, `embedded_chunks: 0`, `dimension: null`. |
| Граница модели | В новом приватном HOME не было весов. `prepare-model` без флага отказал, `prepare-model --offline` на пустом кэше сообщил об отсутствии `model_optimized.onnx`. Загрузка и инференс не выполнялись. Положительная проверка модели и `--semantic` предусмотрены отдельно, не заявлены пройденными. |
| Повтор и отказ | Повтор Wiki и базы проверил receipt. После явного `plugins disable memory-bank` повтор сохранил SHA-256 конфига и оставил плагин выключенным. Последующее явное включение восстановило регистрацию. `--check` базы и Wiki не создал prefix. |
| Статика и тесты | `python3.14 -B -m unittest discover -s tests -v`: 6/6. Ruff, ShellCheck, `compileall`, `git diff --check` прошли. В режиме `--with-tui` прошли 56/56 целевых UI-регрессий, проверка активной палитры, регистрации `arcee` и тот же smoke Memory Bank. |

Повторяемые команды: [README](README.md). Проверки используют синтетические источники и не требуют провайдера. Это не аудит всех возможностей upstream, не проверка семантического поиска без модели и не доказательство безопасности произвольного плагина.

## Предыдущий этап (историческая проверка TUI, до интеграции Memory Bank)

Платформа: macOS arm64; Python 3.14.9, Node 26.12.1, pnpm 12.15.0, uv 0.13.5. Проверялся commit `caafe5389ae585ef77387a962aee05b1bcf17029`, в том числе соответствие публичному `v0.23.3^{}`. Это результат локальной проверки, не сертификат воспроизводимости на всех платформах.

| Что проверено | Наблюдаемый результат |
|---|---|
| Сначала тесты UI, без изменений реализации | Чистый upstream плюс только два обновлённых тестовых файла: 3 ошибки (цвет/края строки, расстояние при 100 и 42 колонках), 53 теста прошли. |
| Тесты установщика до и после реализации | `python3.14 -B -m unittest discover -s tests -v`: сначала 4 отказа, затем 4/4 прошли. Некорректная база не создала prefix; пользовательский каталог, профиль и симлинк остались неизменны. |
| Два независимых способа установки | HTTPS из upstream и `--source` из отдельного checkout с незакоммиченными тестами. Новые prefix, HOME, HERMES_HOME, venv и build caches; обе установки завершены с кодом 0. Исходный checkout не патчился. |
| Результат патча | Ровно 4 файла, их SHA-256 совпали с отобранными исходниками; обе сборки прошли 56/56 целевых регрессий. |
| Собранный JS | Оба `tui/dist/entry.js` побайтово одинаковы; SHA-256 `b1cebf643c3de1ae42315f7a0d5a81d9833963420016268c6ba38a58f06495d2`. |
| Полный набор тестов TUI | Из `source/ui-tui`: `pnpm exec vitest run --maxWorkers=4` — 1982 прошли, 28 пропущены, 0 ошибок. Это не полный набор Python-тестов upstream. |
| Реальный CLI и backend | В каждой установке `tests/smoke.py`: активный Graphite из пользовательского каталога приватной установки; `plugins validate` — `ok: true`, `security scan: safe`, `import registered provider(s): arcee`. Провайдер не вызывался. |
| Интерактивный запуск | `workbench --tui` в терминале 100×30 без ключей показал `Setup Required`; текст `WorkbenchDraftProbe` появился в поле ввода. Черновик не отправлялся; изолированные тестовые TUI и gateway остановлены. |
| Повтор и конфликты | Повтор не изменил SHA-256 пользовательского `config.yaml`, включая добавленный комментарий. После изменения байтов установленной темы получил `drift: profile/skins/claude-graphite.yaml; nothing overwritten`; её изменённый SHA-256 сохранился. |

Для воспроизведения команд установки, unit- и smoke-тестов см. [README](README.md). Установка берёт зависимости из закреплённых upstream lock-файлов. Для визуального smoke используйте пустой профиль Workbench без настроенного провайдера. Отсутствие облачных ключей и внешних non-UI дополнений является условием этой проверки.
