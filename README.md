# Hermes Workbench

**Предварительный снимок (preview):** Graphite, два базовых плагина (Memory Bank и LLM Wiki) и опциональный `/executor` для macOS. Внешние CLI в комплект не входят. Это не полная копия профиля `default`.

Hermes Workbench устанавливает Hermes с интерфейсом Graphite и **двумя включёнными нативными плагинами**. Memory Bank передаёт Hermes планы и состояние работы, а LLM Wiki даёт ему инструменты для поиска по документам и проверки источников. Оба работают в новом профиле. Установка не переносит данные или ключи из других профилей и не требует чат-модели для проверки.

## Установка с TUI и обоими плагинами

Из доверенного checkout или распакованного комплекта, в каталоге с `install.py`:

```sh
WB="$HOME/workbench-local"             # новый каталог, его родитель уже существует
python3.14 -I install.py --prefix "$WB" --with-tui --check
python3.14 -I install.py --prefix "$WB" --with-tui
"$WB/workbench" config get plugins.enabled --json  # memory-bank и llm-wiki
"$WB/workbench" skin list                          # * claude-graphite
"$WB/workbench" --tui
```

Проверенная платформа — macOS arm64. В `PATH` нужны современный Git с `--no-lazy-fetch` (проверен 2.50.1), Bash, `jq`, Python **3.14** (Hermes) и **3.11** (Wiki), `uv 0.13.5`, `node 26.12.1` и `pnpm 12.15.0`. Нужна сеть для GitHub, реестров пакетов и зависимостей Hermes. Установщик не использует `sudo`. Node и pnpm не нужны для варианта без оформления: пропустите `--with-tui` **в обеих** командах. Оба плагина останутся включёнными. Используйте `workbench`, а не `venv/bin/hermes`: launcher задаёт приватные HOME, HERMES_HOME, кеши и PATH.

При первом запуске для разговора с LLM понадобится провайдер. Настройте его через `"$WB/workbench" setup` в этом профиле. Имеющиеся ключи не импортируются; gateway не запускается установщиком.

## Передать задачу внешнему CLI из Hermes (опционально)

В **новом** prefix добавьте `--with-executors` к командам установки и повтора. С `--with-tui` и без него это добавляет нативную команду `/executor` для Codex CLI, Pi, OpenCode и Claude Code. Без флага состав двух базовых плагинов не меняется; установленную базу не надо обновлять на месте. Бинарники, модели, серверы и учётные записи не устанавливаются.

После [настройки выбранного CLI и получателя](EXECUTORS.md) введите в локальном Hermes, например:

```text
/executor probe pi
/executor send pi local-lab@127.0.0.1:8080/lab-coder Предложи имя для функции, которая удаляет дубликаты, сохраняя порядок.
```

Hermes покажет **кому и какой текст** будет передан. `Cancel` ничего не отправляет; `Send once` запускает выбранный CLI и возвращает ответ в Hermes. Он не применяет изменения и не получает историю, файлы текущего проекта, банки или ключи. Адрес в примере не является готовым сервисом: требуется ваш совместимый локальный сервер или доверенный шлюз. За шлюзом возможна **платная отправка внешнему провайдеру**. [Границы, версии и offline-тест](EXECUTORS.md) · [Результаты проверки каждого CLI](EXECUTOR-VERIFICATION.md).

## Где лежат данные

| Каталог внутри `$WB` | Назначение |
|---|---|
| `profile/.memory-bank/` | Планы, решения, статус и handoff. Хук Memory Bank добавляет контекст в prompt, передаёт `MB_PATH` и `MB_SKILLS_ROOT` в сессию и пишет handoff при её завершении. `/mb` — команда skill внутри Hermes, не программа shell. |
| `profile/llm-wiki/` | Корпус Wiki, `raw/`, страницы `wiki/` и локальный индекс `.index/`. Hermes вызывает `llm_wiki_status`, `llm_wiki_search`, `llm_wiki_read`, `llm_wiki_graph`. Это инструменты чтения; они не индексируют и не загружают модель. |
| `home/`, `profile/` | Приватные HOME и HERMES_HOME. Конфиг, правила, история и кеши создаются здесь; окружение вызывающей оболочки не используется для выбора банка или Wiki. |

**Один prefix — один профиль Workbench.** Для второй независимой пары хранилищ повторите установку с новым `--prefix`. Смена рабочего каталога сама по себе не переключает хранилища: нативные адаптеры не ищут `.memory-bank` или `llm-wiki` в текущем проекте, личном HOME или соседнем профиле. Начальное содержимое — только шаблоны: в Wiki индексируются служебные страницы, пользовательских документов нет. Изоляция путей — не песочница ОС. Shell, файловые инструменты агента и явно запущенный пользователем CLI сохраняют его обычные права.

## Пример: добавить источник и найти его в Hermes

Этот пример **изменяет только выбранную новую Wiki**. Выберите новый текстовый файл и передайте его в CLI явно:

```sh
WIKI="$WB/profile/llm-wiki"
SAMPLE=$(mktemp -d)
printf '# Example\n\nLarchBeacon — синтетическая метка.\n' > "$SAMPLE/example.md"
"$WB/llm-wiki" ingest "$SAMPLE/example.md" --root "$WIKI"
"$WB/llm-wiki" index --lexical-only --root "$WIKI"
"$WB/llm-wiki" lint --root "$WIKI"
```

В чате попросите: «Найди LarchBeacon через `llm_wiki_search`, открой найденную страницу через `llm_wiki_read` и укажи строки». Указывать `--root` в нативном вызове нельзя. По умолчанию работает полнотекстовый поиск. Для соседних узлов используйте `llm_wiki_graph`, для проверки свежести индекса — `llm_wiki_status`. После изменения документов повторите `index`. Инструменты Hermes не исправляют устаревший индекс молча.

Семантический и гибридный поиск требуют весов. **Необязательно:** `"$WB/llm-wiki" prepare-model --download` явно скачивает закреплённую модель в приватный кеш, `prepare-model --offline` проверяет её, а `"$WB/llm-wiki" index --root "$WIKI"` строит векторный индекс. По умолчанию веса не скачиваются. Семантический поиск и Docling не входят в проверку этого выпуска. `--wiki` оставлен для отдельной установки одного CLI: он не устанавливает Hermes и **не требуется** для основного варианта.

## Проверка и повтор установки

- На **новом** пути `--check` проверяет источники, патчи, хеши и необходимые версии инструментов во временном каталоге; prefix не создаётся. Он не собирает приложение и не вызывает плагины.
- На **существующем** пути с тем же режимом установщик (в том числе с `--check`) не делает сетевой preflight: он сравнивает receipt, lock и поставляемые файлы, ссылки и исполняемые точки входа. Это не аудит venv, конфигурации или пользовательского корпуса. Повтор не активирует вручную выключенный плагин, не меняет данные и не ремонтирует drift. Для новой версии, другого режима или после прерывания используйте новый каталог. Не переносите venv и не запускайте `hermes update` внутри установки.
- Свежая установка сама вызывает оба плагина через Hermes. Полный тест ниже **создаёт и удаляет две новые установки** (с TUI и без), записывает синтетическую метку в первую и запрашивает вторую из каталога первой. Нужны те же инструменты, сеть и место для двух установок. Уже используемые prefix этому тесту не передаются.

```sh
python3.14 -I -B -m unittest discover -s tests -v
SCRATCH=$(mktemp -d)
python3.14 -I -B tests/smoke_isolation.py --parent "$SCRATCH"
```

## Исходники и лицензии

[Lock-файл](workbench.lock.json) фиксирует Hermes `v0.23.3`, публичные pins Memory Bank и Wiki, разрешённые пути экспорта, хеши адаптеров, патчей и палитры. Установщик получает компоненты из публичных Git-репозиториев: для Memory Bank и Wiki запрашивает метаданные Git без blobs, затем только файлы из списка экспорта. Без поддержки фильтрации сервером установка останавливается. Локальная ветка автора не нужна. Опциональный `--source /path/to/hermes-agent` поддерживается для Hermes с точно совпавшим `HEAD`: берутся только Git-объекты этого коммита. Список источников, изменения адаптеров и авторские уведомления — в [NOTICE.md](NOTICE.md), права упаковки — в [LICENSE](LICENSE). [Результаты проверок](VERIFICATION.md).
