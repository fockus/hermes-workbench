## Установка

Для единой новой установки используйте `python3.14 -IB install.py --prefix "$WB" --full-profile --with-tui --with-executors` из корня Workbench на macOS. Из 29 внешних регистраций эта команда запрашивает 26 с `--no-enable`; 63 штатные регистрации повторно не устанавливаются. Это не отчёт об активации. Пакет выбирает `$WB/profile` и `$WB/home` по receipt; launcher — `$WB/workbench`. В этом режиме подмена на `--profile pack` или `--profile base` запрещена, а `omh`, `soul-composer` и `workflows` удерживаются вне активного профиля (скан `caution`). `prepare-runtimes` уже выполнен основной командой; не повторяйте его. Примеры отдельного pack-профиля ниже относятся **только к прежней базовой установке без `--full-profile`**.

Нужен существующий отдельный Workbench `base` или `tui`; для Workflows — Node из TUI или отдельно установленный в `tool-bin`. Используйте **свежий prefix** для полного набора: каталог и venv принадлежат этому Workbench. Из checkout дистрибутива:

```sh
WB="$HOME/workbench-local"
pack() { python3.14 -I -B plugin-pack/install.py --prefix "$WB" "$@"; }
pack inventory                   # только упаковка; без Hermes, сети и плагинов
pack prepare-runtimes             # один раз: код MB, Wiki, Recall, не данные
pack install all                  # штатный Hermes PM, pinned, без автовключения
pack deps codemode                # проверенные по hash Monty wheels, CPython 3.14
pack deps rtk-rewrite             # только macOS arm64: RTK OSS 1.2.0, без init
# После проверки источников, зависимостей и настройки выбранных ниже сервисов:
pack enable covsift --accept-activation
# Если действительно нужны все исходно включённые плагины, с их доступом:
pack enable all --accept-activation
pack status                       # файлы и состояние, не функциональная приёмка
pack run --                       # запустить именно этот профиль по желанию
```

`install` и `enable` также принимают одно или несколько точных имён. По умолчанию используется новый `$WB/plugin-pack/profile` и отдельный `$WB/plugin-pack/home`; хост, его venv и `tool-bin` принадлежат указанному prefix. Для этого профиля запускайте Hermes через `pack run -- …` — не через launcher базового профиля. Установщик не копирует конфигурацию, список skill-ов, ключи или сессии из соседнего профиля. Для интегратора: поставьте обычный skill pack и его чистую стартовую конфигурацию **в этот же профиль**. `--profile base` позволяет установить отдельные дополнительные плагины в прежний профиль; имена `llm-wiki` и `memory-bank` там принадлежат базовому receipt и заменяться не будут. Исходная версия Wiki вновь поддерживает проектные области: выбирайте только те рабочие каталоги, доступ к которым разрешаете.

Установщик возьмёт внешние пакеты из GitHub, а локальные исходники соберёт в собственные детерминированные Git-репозитории под `$WB/plugin-pack/packages`. Полный результат передаётся в `hermes plugins install … --ref <sha> --no-enable --no-deps`. Для каталожных пакетов сохраняется штатная идентичность каталога. При расхождении receipt, отказе admission, удалении записи из каталога или конфликте зависимостей результат **не считается установкой**. Нет `--force`, принятия предупреждений, выдачи tool override или прямого копирования в `profile/plugins`. `install all` перечисляет отказы и возвращает ненулевой код; уже принятые пакеты сохраняются. При сомнениях не включайте их и не ослабляйте защиту. `enable` может запросить отдельное согласие штатного PM на зависимость. `status` сравнивает целевые флаги/присутствие, а не доказывает идентичность произвольно изменённых файлов установленного плагина.

## Что настраивается отдельно

- **CodeMode** — исходный Monty + типизированный Hermes SDK, не compute CLI. Общий режим `optin`. Установщик не применяет необязательный патч к старой базе и не запускает eval или модели. Если нужны `only`/session tool filters, сначала установите совместимость этих API с pin хоста. Не переносите `.deps` с чужой машины.
- **Recall** — самостоятельный `recall_search` с lifecycle hooks; [исходники отдельного сервиса](services/recall) не являются второй регистрацией. В поставке нет service URL по умолчанию. Владелец разворачивает собственный loopback-сервис с отдельным `HERMES_HOME`, разрешает нужные области индексации, затем задаёт `plugins.entries.recall.settings.service_url`. Не направляйте его на произвольный уже запущенный локальный сервис: loopback сам по себе не подтверждает принадлежность профилю. Для семантического поиска нужны отдельные совместимые лицензированные веса и tokenizer. Пин хоста, FTS5 и прямые зависимости сервиса — условия его эксплуатации, не доказательство работы. Без выбора владельца служба, обработка вложений и модели не запускаются установщиком.
- **Tavily** — hosted MCP, свой ключ/поддерживаемый вход и совместимый HTTP MCP transport. **OMH** — реальный bridge с закреплённой ревизии; CLI/каталог ролей и необязательный Jev — отдельные компоненты. Свою OMH home задайте отдельно. У **RTK** нужен именно бинарник с `rewrite` в пути Workbench, а не оболочка, разрешающая только несколько команд; на другой платформе в этом выпуске нет проверенного asset pin. Свои токены, SSH/account bindings, каталоги документов и модельные aliases не переносились.
- **Workflows** использует Node и исходный `subagents`. Для полного runtime при установке извлекается один неизменённый файл из integrity-pinned npm-архива; можно передать его как `--workflows-archive PATH`. Это чтение данных, не `npm install`. У **Soul Composer** есть оригинальный механизм сборки, но нет личного SOUL, team/recipes и bricks. Не используйте его против действующего домашнего профиля.
- `data-toolkit` передаёт исходный `python_dependencies` в штатный PM (список в каталоге). Эти диапазоны — не lock всех транзитивных библиотек; при конфликте с зависимостями данного Hermes устраните несовместимость, не подменяйте пакет. OCR и модели Docling не скачиваются упаковкой. Для `keep-going` и `heartbeat` переданы общие параметры, но не cron или адреса доставки. У `project-memory-bank` внутренний `enabled` не отменяет внешнего `disabled`.
- В исходной настройке Recall были ограничения model/provider overrides. Их значения привязаны к оператору: не переносим ни разрешения на override, ни пустой список с более широким смыслом. Wiki runtime_root вычисляется внутри prefix. OMH home, частные адреса и ключи оставлены владельцу; никакой автоматической привязки к чужому сервису.

## Смежные поверхности — не прибавлять к 92

- **6 Desktop:** `autorag`, `board-insights`, `kanban-gantt`, `memory-wiki`, `omh`, `quota`. Это `desktop/` тех же pinned-пакетов; исходные JS-файлы сверены отдельно. У автора установка наблюдалась, активация не установлена. Для собственного Desktop/webapp с тем же изолированным home: `pack desktop-install all --accept-activation` (или имя) вызывает штатный Desktop installer по commit; Desktop может загрузить код при следующем сканировании. Персональные `.hermes-package.json` не копируются.
- **43 provider-plugin:** отдельно проверяются blob-ы закреплённого host; `available` не означает выбранный провайдер или действующую подписку. **3 службы:** gateway, Recall, неклассифицированная vendor-служба. Никакой launchd-регистрации, личных plist или работающих процессов не воспроизводится. Для последней сначала установите её назначение и владельца; не запускайте её от имени pack.
- **16 plugin skills** остаются у исходных пакетов (список `separate.plugin-skill` в каталоге), а не у отдельного установщика навыков. Отметки `visible`, `installed-not-visible` и `owner-disabled` не нужно выравнивать принудительным глобальным копированием: видимость задают host, состояние и регистрация владельца. Включены оригинальные `data-toolkit:analysis`, `workflows:workflow-patterns`, `llm-wiki:work-with-wiki`, шесть Tavily, четыре AutoRAG, два Teammates и один Quota.

[Права и источники](NOTICE.md). Базой аудита были инвентаризация default и закреплённые исходники перечисленных компонентов. В этом переносе проверялись только состав, источники, Git/SHA, упаковка, лицензии и отсутствие локальных параметров; плагины, upstream installers, модели, Claude Code и функциональные тесты **не запускались**.
