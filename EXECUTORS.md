# Внешние исполнители: разработка и ревью по переданному тексту

`/executor` — ручная команда локального Hermes CLI/TUI, не инструмент модели. Она запускает выбранный CLI и показывает его результат прямо в Hermes. Подходит, чтобы получить фрагмент кода, предложить правку или обсудить небольшой diff. Пользователь сам решает, что применить. Команда не отправляет историю диалога, не собирает diff, не открывает репозиторий по имени и не связывает ответ со следующим модельным вызовом. В gateway, cron и без согласия отправка не поддерживается.

## Включить

1. На macOS установите Workbench по [README](README.md) в новый `$WB` с `--with-executors`. Наличие внешних CLI для установки необязательно. Повторяйте **те же флаги**: установщик сверяет отдельный [lock плагина](executors.lock.json), не меняя пользовательские привязки и маршруты. Для удаления возможности запуска выключите плагин: `"$WB/workbench" plugins disable workbench-executors`.
2. Привяжите **только выбранные доверенные исполняемые файлы** к `$WB/executors/bin/`. Имя привязки: `codex`, `pi`, `opencode` или `claude`. Пример для установленного Pi: `ln -s "$(command -v pi)" "$WB/executors/bin/pi"`; для JS-сборки также `ln -s "$(command -v node)" "$WB/executors/bin/node"`. Перед созданием ссылки проверьте пути и издателя. Виртуальный PATH Hermes не расширяется. Не привязывайте скрипт оболочки, домашнюю папку, конфиг или каталог агента. Другие три CLI для работы Pi не нужны.
3. `"$WB/workbench" executor probe pi` либо `/executor probe pi` запустит **реальные `--version` и help без сети**. Отсутствующая привязка даёт `not configured`; несовпадающая версия — `unsupported version`. Это не проверка авторизации или наличия работающей модели.
4. Подготовьте **свой** совместимый сервис на `127.0.0.1` (порт 1024–65535). Это может быть локальная модель или доверенный шлюз. Если модель внешняя, **вы сами авторизуете доступ для выбранного исполнителя у провайдера в шлюзе** и определяете получателя, тариф, политику хранения и модель. Существующий вход в Codex, Pi, OpenCode или Claude Code **не подхватывается**; прямой запуск с ним в этом режиме не поддерживается. Workbench не устанавливает шлюз, не поднимает неаутентифицированный публичный proxy, не хранит и не запрашивает токены. Клиент не поддерживает передачу секрета даже для первого локального перехода. Если такая схема неприемлема, не включайте маршрут.
5. Создайте `$WB/executors/routes.json` — обычный JSON без ключей, только нужные строки, например:

   ```json
   {"pi":"local-lab@127.0.0.1:8080/lab-coder"}
   ```

   Подставьте имя реального получателя, порт принадлежащего ему сервиса и точный ID модели. Метка — **ваше обозначение**, а не аутентификация порта или downstream-провайдера. Не отправляйте данные, если не знаете, кто держит listener или куда он пересылает запросы. Плагины не определяют владельца по номеру порта.

| Имя | Версия, с которой разрешён запуск | Что требуется от endpoint |
|---|---|---|
| `codex` | `codex-cli 0.170.0` | OpenAI Responses SSE, `/v1/responses` |
| `pi` | `1.5.0` | OpenAI-compatible Chat Completions SSE, `/v1/chat/completions` |
| `opencode` | `opencode v2.0.18` | OpenAI-compatible Chat Completions SSE, `/v1/chat/completions` |
| `claude` | `2.1.327 (Claude Code)` | Anthropic Messages SSE, `/v1/messages` |

## Отправить задачу

В **локальном** сеансе Hermes введите `/executor send ИМЯ ПОЛНЫЙ_МАРШРУТ ТЕКСТ`. В отдельном терминале доступна та же команда, например:

```sh
"$WB/workbench" executor send pi 'local-lab@127.0.0.1:8080/lab-coder' 'Review: def identity(x): return x'
```

Маршрут должен буквально совпасть с конфигурацией выбранного CLI. Проверьте **полный текст и получателя** на экране согласия, затем выберите `Send once` или в отдельном терминале введите `SEND`. По умолчанию — отказ. Пайп, отсутствие интерактивного подтверждения и отмена не запускают задачу. Используйте одинарные кавычки в shell-примерах: shell пользователя обрабатывает строку **до** входа в Workbench. Внутри `/executor` оболочка не используется. CLI получает задание через stdin, без подстановок `$()`, `;` или передачи путей в качестве файлов.

**Цена и данные.** Вставленный код — это данные, разрешаемые к передаче; удалите ключи, персональные данные и чужой закрытый код. Клиент добавляет собственные служебные инструкции и метаданные. Сам endpoint может делать внешние платные вызовы; один запуск CLI не обязательно означает один запрос или ограничение цены (например, OpenCode может отдельно запросить заголовок). Отмена/таймаут не отзывает уже отправленные данные. Локальная командная строка и история Hermes могут сохранить введённый текст. Лимиты: до 16 KiB текста, до 256 KiB суммарного stdout/stderr, до 60 секунд для ответа; проверки запуска и готовности ограничены отдельно.

## Граница реализации

- Штатные `register_command`, `register_cli_command` и `ask_choice` из Hermes `v0.23.3`; нет внешнего оркестратора, фоновой очереди и модели, которая сама выбирает исполнителя. Другие экземпляры Hermes не создаются. Приватных пакетов и кода поставщиков CLI в дистрибутиве нет. Код плагина — часть Workbench под его [лицензией](LICENSE).
- Штатный `plugins/delegation/default` маршрутизирует дочерние **Hermes** по model/provider; Codex runtime/ACP — транспорты модели и беседы, а не ручная выдача одного разрешённого текста конкретному CLI. Плагины провайдеров для этой функции не включаются. Адаптеры Memory Bank на закреплённом коммите интегрируют банк в клиент; `adapters/pi_native_subagents.mjs` требует RPC другого пакета. Эти интеграции не переустанавливаются и не используются как разрешение на запуск.
- Сеанс создаёт новые HOME, XDG и cwd под приватным `$WB/tmp`, а после завершения удаляет их. Не наследуются PATH, окружение модели, пользовательские конфиги или логины. macOS Seatbelt ограничивает чтение содержимого обычных файлов средой CLI/системными runtime и временным каталогом, запись — временной областью, сеть — согласованным loopback-портом; при `probe` сеть запрещена. Это не контейнер или защита от злонамеренного оператора/бинарника: например, метаданные файлов не полностью скрыты. Нужен доверенный локальный аккаунт, доверенный бинарник и защищённый endpoint. При недоступном `sandbox-exec` нет незащищённого fallback.
- Codex использует пустой Git-репозиторий, `exec --sandbox read-only`, без shell и multi-agent. В Pi выключены инструменты, расширения, MCP и контекст проекта. Claude запускается в `--bare` без инструментов и MCP. OpenCode использует нативные `serve --stdio` и `run --server`: отдельный loopback-порт со случайным одноразовым паролем между собственными процессами и запрет разрешений на инструменты. Он не подключается к личному фоновому сервису. `--auto`, `--trust`, permission bypass и выдача прав на рабочую копию не используются. Специально предоставлять agent shell, хостовые файлы или дополнительные сетевые адреса нельзя.
- Версии сверены с локальным help и [Codex](https://developers.openai.com/codex/noninteractive/), [Pi](https://pi.dev/docs/latest/cli), [OpenCode V2](https://opencode.ai/docs/cli/), [Claude Code](https://code.claude.com/docs/en/cli-reference). Для другой версии сначала нужен новый тест и обновление версии адаптера. Совместимость на Linux/Windows не заявляется.

## Проверить без модели и личной авторизации

```sh
python3.14 -I -B -m unittest discover -s tests -v
# Только новый prefix с флагом --with-executors, до ручной настройки его bin и routes.json:
python3.14 -I -B tests/smoke_executor_real.py "$WB" \
  --codex "$(command -v codex)" --pi "$(command -v pi)" \
  --opencode "$(command -v opencode)" --claude "$(command -v claude)" --node "$(command -v node)"
```

Unit-тест компилирует временные бинарники-фикстуры (`cc`) для проверки аргументов, cwd, разрешений, ошибок, таймаута и предела вывода. В отдельном smoke настоящие Hermes и четыре настоящих CLI. **Только** endpoint модели и выбор оператора для синтетической метки — фикстуры. Сервер на loopback проверяет входящую метку и отвечает отдельной случайной строкой; проверяется, что строка дошла обратно через диспетчер Hermes. Smoke не запускает обучение или инференс, не проверяет качество ответов и коммерческий API. Установка самого Workbench, в отличие от этих тестов запуска, требует доступа к публичным upstream и реестрам.
