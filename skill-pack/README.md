# Набор скилов default для Workbench

`manifest.json` фиксирует 90 разных имён: 89 видимых в исходном default и установленный, но не видимый `sdlc-review`. Это инвентарь **скилов**, а не обещание, что после установки все имена будут видимы на любой ОС или что плагины/агенты работали. Содержимое исходного профиля не является входом публичной установки.

На macOS для нового prefix из корня дистрибутива: `python3.14 -IB install.py --prefix "$WB" --full-profile --with-tui --with-executors`. Если нужно добавить только навыки к уже установленной базе/TUI этого выпуска:

```sh
python3 -IB skill-pack/install.py install --prefix "$WB"
```

`WB` — абсолютный канонический путь к установке. Из **61 проверенного дополнительного дерева** команда выбирает **57**: 35 из `skill-pack/payload`, 9 из `review-skills/payload`, 11 авторских консолидаций и 2 редакции из `editions/`. Это не размер всего профиля. Байты и notices уже в комплекте. Требуются и `safe`, и штатное разрешение `community`; команда не включает плагины и не исполняет навыки.

Дополнение [«Восстановленные исходники и остаток по правам»](recovery/README.md) входит в поставку, но не меняет выбор активных имён. В нём — чистые справочники Orchestra, переносимые дополнения к двум навыкам, точные дельты MB/Wiki и отдельно проверенные исходники управляющего OMH.

Текущий общий каталог OMH — 155 имён (ранний снимок — 153); это не 155 видимых скилов default.

### Коллизии и отличия

- `requesting-code-review` и `test-driven-development`: неизменённые варианты Superpowers сохранены с MIT notices в дистрибутиве; одноимённые обязательные варианты Hermes не подменяются. Для `systematic-debugging` действуют оба ограничения выше.
- `subagent-driven-development` у Hermes **опционален**, а не обязателен. На чистом base устанавливается полный Superpowers, включая его `scripts/`, до `executing-plans`. Если оператор уже выбрал несовместимый вариант, установка откажет до публикации новых деревьев.
- `grill-me` — отдельный официальный **опциональный** skill, его полное дерево добавляется через штатный карантин; `grilling` — независимый Matt Pocock. `llm-wiki` — не одноимённый **опциональный** skill Hermes и не квалифицированный скил плагина. Здесь поставляется та же проекция публичного репозитория автора, что выбрана для default (`SKILL.md`, `LICENSE`, `agents`, `references`, `scripts`). Два файла runtime в неопубликованном checkout отличаются от публичного pin. Оба недостающих файла поставляет `plugin-pack/base-overlays/llm-wiki/runtime-changes`; сам по себе базовый pin не является точной копией.
- Локальные документы `codex` и `diagnosing-bugs` отличаются от публичных. Поставляются оригинальные публичные версии и переносимые дополнения в `recovery/companions/`. `memory-bank` использует другую публичную ревизию: в проекции источника 21 изменённый файл между коммитами, не считая локального рабочего дерева и патчей Workbench. Ревизии default `memory-bank` и `llm-wiki` не выдаются анонимным `git fetch` публичных upstream; недостающие байты проекций поставляются через соответствующие `plugin-pack/base-overlays`, без доступа к этим Git-ревизиям при установке.
- Собственные очищенные тексты и дополнения `codex` / `diagnosing-bugs` — MIT (Hermes Workbench contributors); решение владельца не меняет сторонних лицензий или допуска. Не добавляйте `editions/`, `reading-only/` или `recovery/` в `skills.external_dirs`.
- Не перепечатываются `writing-skills/references/anthropic-best-practices.md` и `writing-clearly/{SKILL.md,references/infostyle-ru.md,references/yasno-ponyatno.md,references/plain-english.md}`: вместо оригиналов — самостоятельные тексты. В обеих копиях `lm-evaluation-harness/references/benchmark-guide.md` — только ссылка на закреплённый источник, без примеров HumanEval и Winograd.

`private_review.py` — **необязательный**, отдельный инструмент владельца. По `--profile /absolute/owner/profile --out /new/private/directory` он может сохранить локально эти 30 файлов и два изменённых документа (`codex`, `diagnosing-bugs`) для ручного разбора, с закрытыми правами и приватными checksum. Проверяет границы, набор путей и распространённые форматы секретов; это не доказательство отсутствия персональных данных. Не копирует логи, конфиги или переписку и не умеет устанавливать/публиковать результат. Не помещайте эту копию в Git или публичный архив.

### Статическая проверка без профиля и LLM

```sh
python3 -IB skill-pack/install.py verify                 # локальные файлы, modes, Git trees, notices
python3 -IB skill-pack/install.py verify --sources       # дополнительно сверить два оригинальных дерева у издателей
python3 -IB skill-pack/recovery/verify.py
python3 -IB skill-pack/provenance.py --providers plugin-pack/catalog.json
```

`provenance.py --repo OWNER/PROJECT=/path/to/clone …` дополнительно сверяет все 10 закреплённых источников по объектам Git: деревья хоста, байты base-документов, состав каталогов, проекцию wiki, режимы и лицензии. Ни одна из этих проверок не запускает принесённый скрипт. Для установки все новые директории сначала проходят повторный штатный карантин с `community` и `should_allow_install`; требуются одновременно `safe` и разрешение. Имеющаяся одноимённая директория принимается только при полном совпадении ожидаемой установки Hub; чужие файлы не изменяются. Получение источников и допуск предшествуют первой публикации в профиль. Ошибка диска при последующих штатных перемещениях не транзакционна.
