# Scoped Hermes Kanban worker preflight

Use these checks to locate the first unmet prerequisite. They are not a tested launch command. Stop before dispatch if a check fails.

1. **Bind the task and its owner.** Pin `HOME`, `HERMES_HOME`, `HERMES_KANBAN_HOME`, `HERMES_KANBAN_DB` and `HERMES_KANBAN_WORKSPACES_ROOT` per invocation. Verify the existing card ID, current assignee, provider/model and run count; after reassignment, expect the *new* assignee. Where supported, disable `kanban.dispatch_in_gateway` and `kanban.notify_in_gateway` before setting `gateway.standalone: true` on the test profile. Check `hermes -p "$profile" gateway status`: recognition of standalone is evidence of routing configuration, not a running owner. Do not force a second owner.
2. **Test filesystem permissions without changing the card.** In the candidate worker policy, open the existing scratch DB with `os.O_RDWR | os.O_NOFOLLOW` and close it without writing. Require the same open to fail on the live DB and on the checker. Exercise SQLite commit/lock/journal behavior on disposable data if needed: opening the DB alone does not prove a commit. Check the installed launcher's own lock requirements without granting writes to the production installation.
3. **Test IPC separately.** With the gateway stopped, exchange one byte over the exact approved socket and require a sibling socket bind to be denied. This proves the policy, not who will own the socket. Before handing off a card, verify the live owner's identity; never substitute the default gateway for a missing test owner.
4. **Test model access inside the same boundary.** A named profile can share an installation's managed runtime whereas a separate root need not. `--no-credentials` prevents copying credentials, not necessarily inherited access. If the native client needs a credential-bearing owner record, explain the full authority its key grants and obtain permission for that exact scope; do not copy, print or persist the key. Verify the native owner and expected model ID via authenticated `/v1/models`, then test bounded generation with a harmless prompt and an exact expected reply. Record HTTP result, model, text match and elapsed time separately from the outer command's exit: an observed response and a wrapper timeout can both be true.
5. **Separate operator handoff from acceptance.** Before handing over a parent-only command, verify that the artifact exists, actually includes the bounded dispatch, passes its nonmutating check and refuses execution from a supervised child. A launcher that only starts the gateway is not that command. After the operator acts, read the same card and run record before suggesting any retry. Require a worker-attributed run and the expected completion result; neither a direct model reply nor a successful preflight supplies them.
